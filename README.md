# 智能火情巡检小车

本项目是一套基于 **STM32H7** 的智能火情巡检小车系统。小车能够沿黑线自动巡检，使用摄像头与热成像数据进行火情识别；当识别到 `fire` 火情后，STM32 会立即控制小车停车、点亮报警 LED，并将火情图像上传到 PC 端 GUI 界面显示，同时播放报警音效。

当前仓库默认分支：`fire_alarm`

## 项目功能

- 自动循迹巡检：通过左右两个灰度/光敏传感器识别黑线与白纸，控制双电机完成直行和转向。
- 本地火情识别：深度学习模型已部署在 STM32H7 端，PC 端不再承担模型推理任务。
- 火情自动响应：识别到 `fire` 后，小车立即停止，LED1 点亮，等待 5 秒后自动恢复原巡检速度继续行驶。
- 火情图像上传：只有识别到火情时，STM32 才上传对应的可见光图像，减少通信压力。
- PC 端监控报警：Python GUI 接收 STM32 上传的数据，显示可见光图像、热图/快照和融合图；收到火情事件后，面板报警灯亮起并播放警报音效。

## 系统结构

```text
灰度传感器 ─┐
            ├─> STM32H7 ──> 电机驱动 ──> 小车运动/停车
OV2640 摄像头 ┤      │
MLX90640 热成像 ┘      ├─> 火情识别模型 ──> LED1 报警
                       │
                       └─> 串口/网络链路 ──> PC 端 Python GUI
```

各模块之间的关系如下：

1. 灰度传感器负责判断黑线位置，STM32 根据左右传感器状态控制电机循迹。
2. 摄像头和热成像模块负责采集环境图像数据，STM32 在本地完成火情识别。
3. 当识别结果为 `fire` 时，STM32 直接执行停车和亮灯，不需要 PC 发送 `STOP` 或 `CAPTURE` 命令。
4. PC 端只负责接收、显示和报警，不参与小车运动控制和模型判断。

## 主要硬件

| 模块 | 作用 |
| --- | --- |
| STM32H7 | 主控，负责图像采集、火情识别、循迹控制和火情响应 |

| LED1（PE13） | 火情报警指示灯 |
| PC 上位机 | GUI 显示火情图像并播放报警音效 |

## 软件设计

本项目的软件设计围绕“端侧自主识别、火情本地响应、PC 端监控展示”展开。火灾识别模型的训练、量化与部署流程参考了以下项目说明：

[https://github.com/time-cat/FireAlarm](https://github.com/time-cat/FireAlarm)

软件链路可以分为四个部分：

1. 数据预处理与多模态融合
   - 系统使用可见光图像和热成像数据作为输入。
   - RGB 图像提供颜色、纹理和火焰形态信息。
   - 热成像数据提供温度分布信息，能够增强火情区域的判别能力。
   - 两类数据经过空间对齐、尺寸统一和归一化后，组合为融合输入，用于后续模型训练与推理。

2. 深度学习模型训练
   - 识别任务按照 `normal / warning / fire` 三类进行分类。
   - 模型输入包含 RGB 与热成像融合后的特征。
   - 网络结构采用轻量化 CNN，适合在 STM32H7 这类资源受限的嵌入式平台上部署。
   - 训练完成后，模型会导出为适合后续量化和嵌入式部署的格式。

3. 模型量化与 C 代码部署
   - 为了降低 Flash、RAM 和计算量占用，模型经过 int8 量化处理。
   - 量化流程会对权重、偏置和中间激活进行压缩，使模型能够在 MCU 端运行。
   - 最终生成的 C 语言推理代码被集成到 STM32 工程中，由 STM32H7 在本地完成火情识别。

4. 端侧识别与报警联动
   - STM32 持续采集图像并构建模型输入。
   - 当模型输出类别为 `fire` 时，STM32 立即执行停车、亮灯和图像上传。
   - PC 端只负责接收和显示火情信息，不再参与模型判断，也不再向 STM32 下发停车或拍照命令。

这种设计的优点是识别和控制都在小车本地完成，响应速度更快；PC 端只作为监控界面使用，整体系统更加独立、稳定。

## 固件说明

Keil 工程文件：

```text
MDK-ARM/CAM1.0.uvprojx
```

主要代码位置：

| 文件 | 说明 |
| --- | --- |
| `Core/Src/main.c` | 主循环、摄像头采集、火情识别、循迹控制、火情停车逻辑 |
| `Core/Src/motor.c` | 电机 PWM 控制 |
| `Core/Src/gpio.c` | GPIO 初始化，包括 LED、按键、循迹传感器 |
| `Core/Src/thermal_stream.c` | 热成像/可见光图片上传协议 |
| `pc_receiver/mlx90640_viewer.py` | PC 端 GUI、图像接收、报警灯和警报音效 |

火情响应逻辑：

1. STM32 持续采集图像并运行火情识别。
2. 识别到 `fire` 后，立即停止电机。
3. PE13 控制的 LED1 点亮。
4. STM32 上传当前火情可见光图像和火情事件数据。
5. 停车等待 5 秒。
6. LED1 熄灭，小车恢复原来的循迹速度继续巡检。

## PC 端运行方法

进入仓库根目录后安装依赖：

```powershell
cd pc_receiver
python -m pip install -r requirements.txt
```

启动 GUI：

```powershell
python mlx90640_viewer.py
```

也可以从仓库根目录启动：

```powershell
python pc_receiver\mlx90640_viewer.py
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--bind 0.0.0.0` | 设置监听地址，默认监听所有网卡 |
| `--port 8888` | 设置接收端口 |
| `--headless` | 无界面运行，用于调试接收链路 |
| `--no-alarm` | 不播放报警音效 |
| `--self-test` | 无硬件协议自检 |
| `--flip-x` | 水平镜像显示图像 |

协议自检：

```powershell
python pc_receiver\mlx90640_viewer.py --self-test --no-alarm
```

## 通信协议简述

STM32 与 PC 端使用统一的 `MLX4` 二进制帧格式，主要帧类型如下：

| 帧类型 | 含义 |
| --- | --- |
| `0x01` | 实时热成像温度帧 |
| `0x02` | 可见光图像分片 |
| `0x03` | STM32 识别到火情后的热图快照/火情事件 |
| `0x7F` | 状态或错误信息 |

可见光图像为 `240×240 RGB565`，图片数据会拆分为多个分片发送，PC 端自动重组并显示。

## 演示流程

1. 打开 PC 端 GUI 程序。
2. 给 STM32 小车上电。
3. 小车根据灰度传感器沿黑线开始巡检。
4. 摄像头和热成像模块同步采集环境信息，STM32 本地运行火情识别。
5. 当摄像头画面中出现火情并识别为 `fire` 时：
   - 小车立即停车；
   - LED1 点亮；
   - PC GUI 显示火情图像；
   - GUI 报警灯亮起并播放警报音效。
6. 停车 5 秒后，小车自动恢复循迹巡检。
